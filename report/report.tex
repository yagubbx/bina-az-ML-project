\section{Introduction}
Property listings combine numeric characteristics, location and categorical information. They also contain repeated records, missing values and unusual prices. This makes them useful for studying both model implementation and the practical effects of data preparation. The target in this project is an \emph{asking price}; the dataset does not establish the final transaction price.

Task A predicts price with a decision tree trained on natural-log price. Task B predicts a price tier with a classification tree and an SVM. The main contributions are a shared data pipeline, NumPy implementations of both algorithms, a non-linear SVM extension, and a comparison with matched scikit-learn baselines. The purpose is to understand model behaviour and explain errors, rather than report only the strongest metric.

\section{Background}
Decision trees split a feature space into regions. A classification tree selects splits that reduce class impurity, while a regression tree reduces within-node target variance. Their stopping rules limit complexity. The scikit-learn tree documentation provides the reference behaviour used in the comparison~\cite{trees}.

A soft-margin SVM balances a weight penalty with hinge loss. Pegasos optimizes this objective using sub-gradient updates and a decreasing learning rate~\cite{pegasos}. Random Fourier features (RFF) approximate a shift-invariant kernel through an explicit random mapping~\cite{rff}. This project uses that mapping with the same linear solver, avoiding a full training kernel matrix.

\section{Data and Preprocessing}
\subsection{Dataset and cleaning decisions}
The source is the Bina.az Sale Project dataset published on Kaggle~\cite{data}. Table~\ref{tab:data} summarizes the data used here. The pipeline retains the first observed record for each listing URL in file order. This removes 36,321 repeated snapshots, leaving 64,454 rows. There are no additional exact-row duplicate removals and no rows removed by the positive-price or AZN-currency checks in this run. Different URLs may still describe the same property.

Numeric strings are converted to numbers. Area values expressed in sot are multiplied by 100 to obtain square metres. Floor information is separated into the current floor and total number of floors. Non-positive area and room values, inconsistent floors and invalid geographic coordinates become missing values. Geographic validation checks coordinate ranges, not the correctness of each location.

Missing numeric values use training medians. Missing categories receive a dedicated value. Numeric inputs are clipped using their training 1st and 99th percentiles. The model also receives missing-value indicators and one-hot categorical columns. Unseen categories map to all-zero indicators. These steps produce 179 input features. Clipping applies to predictors, not to the target price.

\subsection{Features and target leakage}
Numeric predictors are area, rooms, floor, total floors, land area, latitude and longitude. Categorical predictors are location, city, building type, property category, repair status, bill-of-sale status and mortgage availability. Absent flags remain missing rather than becoming a confirmed negative answer. For example, 6,094 cleaned rows have missing room counts and 54,823 have missing land area.

The columns \texttt{unit\_price} and \texttt{total\_price} are excluded from both tasks: one is a price-derived quantity and the other restates the target. The feature whitelist also excludes names, raw addresses, listing identifiers, scraping metadata and free text. Listing URLs serve only to remove repeated records; they are not model inputs.

\subsection{Targets, splits and exploratory analysis}
A seeded permutation reserves 70\% of the cleaned data for training. Its median price, 210,000 AZN, defines the premium label. The remaining data are divided into validation and test partitions stratified by that label. Thus, validation and test are stratified; the initial training reservation is random. Ties at the median belong to the standard class. No held-out price contributes to the threshold.

Exploratory plots use training data only and cover raw and log-price distributions, area versus price, room counts, coordinates and tier balance. Prices have a long upper tail. The training 90th percentile is 520,000 AZN. Location is informative but coverage is uneven. Median imputation, category vocabularies and scaling are fitted after splitting, so held-out rows cannot influence these statistics.

\section{Method}
\subsection{Decision tree}
For class proportions $p_k$, the supported impurities are
\begin{equation}
G=1-\sum_k p_k^2,\qquad H=-\sum_k p_k\log_2 p_k.
\end{equation}
Regression uses $I=N^{-1}\sum_i(z_i-\bar z)^2$, where $z_i=\log(y_i)$ and $y_i$ is price. The gain of a split into left and right children is
\begin{equation}
\Delta I=I_P-\frac{N_L}{N_P}I_L-\frac{N_R}{N_P}I_R.
\end{equation}
For each feature, the implementation sorts values and tests thresholds between distinct adjacent values. Cumulative class counts or target sums allow candidate evaluation without rebuilding each child for every threshold. Recursion chooses the largest positive gain that satisfies the leaf-size constraint.

Growth stops at maximum depth, an insufficient split size, a pure or unsplittable node, or an insufficient weighted impurity decrease. The API supports \texttt{max\_depth}, \texttt{min\_samples\_split}, \texttt{min\_samples\_leaf} and \texttt{min\_impurity\_decrease}. Experiments vary depth and leaf size, while the other two retain defaults of 2 and 0. Classification leaves return a majority class and class-frequency probabilities. Regression leaves return a mean log price, exponentiated for AZN evaluation. No retransformation bias correction is applied.

Feature importance sums sample-weighted impurity reductions for each feature and normalizes the totals. It measures use within this fitted tree, not a causal effect on price.

\subsection{Pegasos SVM}
Training labels are mapped to $y_i\in\{-1,+1\}$. With score $f_i=\mathbf w^\top\mathbf x_i+b$, the objective is
\begin{equation}\label{eq:objective}
J=\frac{\lambda}{2}\|\mathbf w\|^2+
\frac{1}{n}\sum_{i=1}^n\max(0,1-y_i f_i).
\end{equation}
The implementation shuffles rows using seed 42 and processes mini-batches of at most 256 examples. At step $t$, let $B_t$ be the batch and $A_t=\{i\in B_t:y_i f_i<1\}$. With $\eta_t=1/(\lambda t)$, the update is
\begin{align}
\widetilde{\mathbf w}&=(1-\eta_t\lambda)\mathbf w+
 \frac{\eta_t}{|B_t|}\sum_{i\in A_t}y_i\mathbf x_i,\\
b&\leftarrow b+\frac{\eta_t}{|B_t|}\sum_{i\in A_t}y_i,\\
\mathbf w&\leftarrow\min\left(1,\frac{1}{\sqrt{\lambda}\|\widetilde{\mathbf w}\|}\right)\widetilde{\mathbf w}.
\end{align}
Projection is applied only when the norm exceeds $1/\sqrt{\lambda}$. The bias is separate and unregularized. Gradients average over the full batch, including examples with zero hinge gradient. The full training objective is recorded after every epoch; stochastic updates need not reduce it at every epoch.

Inputs use training means and standard deviations. The class prediction follows the score sign, with zero assigned to premium. The reported geometric margin width is $2/\|\mathbf w\|$. Points with signed margin at most one form the reported support mask. These are margin-active points under the primal model, rather than exact non-zero dual coefficients. An alternative $0.1/\sqrt{t}$ schedule is available for sensitivity analysis.

\subsection{Non-linear extension}
RFF maps standardized $\mathbf x$ to
\begin{equation}
\phi_j(\mathbf x)=\sqrt{2/D}\cos(\boldsymbol\omega_j^\top\mathbf x+u_j),
\end{equation}
where $\boldsymbol\omega_j\sim\mathcal N(0,2\gamma I)$ and $u_j\sim U(0,2\pi)$. The approximate kernel is $\exp(-\gamma\|\mathbf x-\mathbf x'\|^2)$. The mapping uses a fixed seed, and the selected configuration has $D=512$. Both the NumPy and scikit-learn RFF models use the same mapping. This permits a comparison of solvers with shared inputs.

\section{Experimental Setup}
\subsection{Selection and baselines}
The regression tree search covers depths $\{3,6,10,14,18\}$ and leaf sizes $\{5,20\}$. Classification uses depths $\{3,6,10\}$, both leaf sizes, and Gini or entropy. Selection minimizes validation log-RMSE for regression and maximizes validation F1 for classification.

The linear SVM search uses $\lambda\in\{10^{-4},10^{-3},10^{-2}\}$ and 20 or 40 epochs. Initial RFF candidates combine these settings with $D=128$ and $\gamma\in\{0.01,0.1\}$. An extended validation search uses $D=512$, 80 epochs, $\lambda\in\{10^{-4},10^{-3}\}$ and $\gamma\in\{0.001,0.003,0.01\}$. The final settings appear in Table~\ref{tab:config}. Search records remain in \texttt{tuning.csv}.

Scikit-learn trees use the same criterion and stopping settings. SVM baselines use \texttt{SGDClassifier} with hinge loss, L2 regularization, $\texttt{alpha}=\lambda$, matched epochs, \texttt{tol=None} and seed 42. A \texttt{Pipeline} includes scaling and, where needed, RFF. Its default optimal learning schedule and lack of the same explicit projection mean that this is a matched-objective comparison, not an identical optimizer~\cite{sgd}.

Two additional regression baselines predict the training mean (324,292.79 AZN) or median (210,000 AZN) for every held-out listing. They require no held-out statistics. Final models fit the original training partition; validation rows are not added after selection.

\subsection{Metrics and cross-validation}
Regression metrics are RMSE and MAE in AZN, price-scale $R^2$, and RMSE of natural-log prices. Classification metrics are precision, recall, F1 and ROC-AUC, with premium as the positive class. AUC uses tree probabilities or SVM decision scores. The NumPy metric functions include tied-rank AUC handling. A high F1 must not be described as the same percentage accuracy.

Three-fold cross-validation runs within the training partition using the fixed selected configurations. Each fold refits preprocessing and recalculates its price-tier threshold. Fold means and sample standard deviations are reported separately from the single test result. They describe variation within training data; they are neither test confidence intervals nor nested model-selection estimates.

The validation search determines the recorded final settings. However, historical test results were already inspected during development, before the search was extended. Therefore, the test partition is not a fresh blind evaluation. This limitation remains even though the selection code ranks candidates using validation scores only.

\subsection{Correctness and repeatability}
The built-in \texttt{--check} command covers tiny tree comparisons with scikit-learn, stopping parameters, refitting and class probabilities. SVM checks cover a hand-calculated update, repeatability and objective behaviour. Further checks cover metrics, preprocessing state, split handling and the RFF kernel approximation. These checks passed in the recorded project workflow; they are finite sanity checks, not a proof of correctness for every input.

The reported run uses Python 3.11.9, NumPy 1.26.4, pandas 2.2.2, matplotlib 3.8.4 and scikit-learn 1.4.2 on Windows. The latter four versions are pinned in \texttt{requirements.txt}. Transitive versions, including SciPy and threadpoolctl, are recorded in metadata but are not a complete environment lock. One BLAS thread is used. Fit and prediction times exclude shared cleaning and feature preparation; SVM timing includes its scaling and mapping. Timings are a single run and vary with hardware and load.

The linear SVM reaches F1 0.8553, above the RFF model's 0.8478 for the tested configurations. The small gaps between implementations do not establish statistical superiority.

Table~\ref{tab:regression} shows almost identical regression metrics for the two trees. The NumPy tree improves test MAE by 35.5\% over the median baseline and reduces log-RMSE from 0.8360 to 0.4102. Validation also supports useful learning: tree log-RMSE is 0.3814, compared with 0.8035 for the training-median baseline. Nevertheless, price-scale RMSE remains 6.18 million AZN and $R^2$ is only 0.0105. Log-scale success does not imply accurate predictions for the most expensive listings.

Table~\ref{tab:cv} separates training-fold variation from test performance. The classification tree has stable F1 across the three folds. RFF F1 varies more than linear SVM F1. Regression CV log-RMSE is 0.4020, close to test log-RMSE, while its CV price-scale $R^2$ is $0.4273\pm0.0150$. The much lower test $R^2$ reflects sensitivity to the different target distribution and extreme test values.

The custom regression tree takes 18.081 seconds to fit, compared with 1.773 seconds for scikit-learn. Classification tree times are 9.754 and 1.688 seconds. The NumPy code prioritizes readable algorithm steps, while scikit-learn benefits from optimized tree routines. SVM fit times are closer in this run. They must not be interpreted as general speed guarantees.

\subsection{Validation behaviour}
Figure~\ref{fig:validation} shows the tree trade-off. At depth 18, minimum leaf 5 obtains training log-RMSE 0.2693 but validation log-RMSE 0.4023. Increasing the leaf minimum to 20 raises training error to 0.3448 and lowers validation error to 0.3814. This is evidence that the smaller leaves fit training detail that does not transfer as well.

For classification, Gini at depth 10 and leaf 5 gives validation F1 0.9095. The best entropy candidate reaches 0.9036 at depth 10 and leaf 20. The selected linear and RFF SVMs reach validation F1 0.8577 and 0.8547. RFF does not improve this task over the selected linear model. The search changes feature dimension, bandwidth and epochs together, so it is not a controlled estimate of each factor's separate effect.

\section{Error Analysis and Limitations}
\subsection{Classification errors}
The NumPy tree produces 4,346 true negatives, 509 false positives, 399 false negatives and 4,415 true positives. Table~\ref{tab:confusion} lists the confusion counts for the three custom classifiers. The RFF model detects more premium listings than the linear SVM, but also marks more standard listings as premium, reducing precision and F1.

Linear SVM & 4,125 & 730 & 672 & 4,142\\

For 531 test listings whose location appears fewer than 100 times in training, F1 falls to 0.7740 for the tree, 0.7101 for linear SVM and 0.4322 for RFF. Limited location coverage is therefore an important weakness, particularly for RFF. Group sizes and class balance differ, so small-group F1 should be interpreted with their counts rather than as a precise ranking of locations.

\subsection{Extreme targets and regression errors}
Table~\ref{tab:errors} uses the training 90th-percentile price boundary of 520,000 AZN. The 994 test rows above that boundary account for 99.97\% of total squared error, computed as group size times squared group RMSE divided by the corresponding total. Their MAE is 1,465,850 AZN. The other 8,675 rows have MAE 38,717 AZN, but their $R^2$ is still only 0.0422. Therefore, the regression limitation is not fully resolved by describing the expensive tail.

Source inspection finds a 200 m$^2$ apartment listed at 600,000,000 AZN and a 50 m$^2$, seven-room apartment at 60,000,000 AZN. These values already occur in the original CSV. The restated price fields agree, which confirms internal consistency but not factual accuracy. A land record contains 200,000 sot, correctly converted by the code to 20,000,000 m$^2$; the source area itself remains questionable.

The pipeline does not guess corrected prices or remove test examples because they cause large errors. A future study should verify anomalous records using independent evidence, define a cleaning policy before evaluation, and use a fresh evaluation sample. Retaining the records makes the current main metrics transparent, but does not make the source values reliable.

\subsection{Feature interpretation}
Area has the largest tree impurity importance: 0.5653 for regression and 0.5796 for classification. Latitude and longitude contribute 0.1245 and 0.1152 in regression. Classification also uses longitude (0.1421), land area (0.0779) and latitude (0.0719). The linear SVM's largest positive standardized weights include rooms (1.1788), area (0.8149) and the new-building category (0.4044). The land category has weight $-0.4798$.

These associations match the models' use of size, location and property type. They are conditional on encoding and scaling and are not causal explanations. Correlated features can share importance, and impurity importance can favour features with more candidate split points. The full ranked plots are stored in \texttt{feature\_effects.png}.

\subsection{Scope of the conclusions}
The label is relative to a sample median, not an official definition of luxury housing. Advertised prices differ from final transaction values. A random split of one historical scrape does not establish performance on future market conditions or new regions. Listing-level deduplication does not guarantee property-level independence.

The mean-log leaf prediction targets a different loss from squared AZN error. Exponentiating it without correction can underpredict arithmetic mean price. Predictor clipping can also suppress genuine extreme characteristics. Neither clipping bounds nor preprocessing choices were tested in a separate ablation, so their individual effects are unknown. Historical test inspection, the limited search and only three CV folds further limit generalization claims.

\section{Conclusion}
The NumPy models give results close to the matched scikit-learn baselines. The classification tree performs best among the tested custom classifiers, with test F1 0.9068. The regression tree improves substantially over constant predictors on log-RMSE and MAE, but its low price-scale $R^2$ prevents a claim of reliable valuation across the full dataset. The most useful next steps are evidence-based source validation and evaluation on a new time period. Clear data handling and honest reporting are as important as the model score.
